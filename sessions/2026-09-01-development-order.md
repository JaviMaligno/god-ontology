# Session: Development order and formalization depth

**Date:** 2026-09-01
**Session ID:** S08
**Primary question:** How should the ontology balance breadth, depth, and research priority?
**Dependencies:** commitment ledger, session workflow, treatise outline
**Starting decisions:** primacy of interaction, default acceptance, selective adversarial method

## Starting position

The first seven sessions developed several downstream modules in considerable local detail. The author accepts that work but does not want every newly encountered branch formalized exhaustively. High-level concepts and the global architecture are usually more important, while some apparently attractive claims still require formal testing before they can carry later conclusions.

The author also confirms that the ledger-style table must remain a control mechanism for status, caveat, and provenance.

## Distinctions

| Axis | Question answered |
| --- | --- |
| Commitment status | What does the project currently accept, prefer, test, defer, leave open, or reject? |
| Development depth | Is the claim conceptual, architecturally integrated, locally formalized, or stress-tested? |
| Evidential maturity | Which internal, adversarial, bibliographic, empirical, experiential, or theological supports have been examined? |

These axes are independent. Acceptance does not imply complete formalization, and formal sophistication does not imply acceptance.

## Chosen strategy

Use a breadth-first spiral with selective formal depth:

1. obtain the high-level map;
2. work on the next load-bearing junction at F0–F1;
3. move to F2 only when an explicit trigger appears;
4. reintegrate the result before opening another deep branch;
5. reserve F3 and systematic appendices for the stable backbone.

The current formal work on time, ACO, modality, intervention, and agency is retained as useful conditional architecture. Mind–body metaphysics is now a lateral deferred branch. Earlier unworked backbone concepts take priority.
